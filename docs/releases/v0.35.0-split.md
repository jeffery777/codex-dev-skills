## Compatibility And Boundaries

Add limited skill/agent index-write integration for the accepted GitNexus
`1.6.12`/Node `25.9.0` installation on macOS arm64. A02 exercised stale revision,
actual controller refresh, metadata/registry/sidecar and required internal
freshness checks. Bind accepted local identity and explicit coverage; requalify
affected integration after tool/runtime/dependency updates. Refuse repository
`.gitnexusrc` and same-HEAD refresh. The existing operator CLI selects `1.6.9`.

Preserve the worker's original STOPPED_NO_RETRY: an earlier index stat-cache
baseline differed only in cached ctime, with staged content unchanged; writer
identity is unknown and its second outer freshness API was not run. The
controller's own protected window matched. Do not label the outer run PASS.
Automatic refresh, hooks, query/impact/MCP and other platforms are not added.
FTS remains unavailable/extension-unavailable; no RAM hard cap is claimed.

Core stays at the exact v0.1.0 commit above. Grok's actual thin skill entry and
its version/Core-pin readback remain its owner's required follow-up. The current
orchestrator assigns the single index writer and coordinates readers. Installer
delivery still needs payload S, mapping-only T and the original four isolated
failures rechecked. No real installation or publication is established.
See [audit](../codex-runtime-compatibility-evidence-2026-10-17.md) and
[release assessment](runtime-audit-2026-10-17.md) for evidence and remaining gates.
