## CI And Installer Maintenance

Ready transitions reuse the latest eligible full run for the same PR head. A missing or pending run, or a newer failed run, still blocks readiness. Changed heads still need their own CI and complete Merge Review; this does not introduce selective tests or a new guarantee about a run's original base. The rollout added a bounded workflow transition and trusted-policy readback checks. The final policy uses one approved workflow pin, rather than retaining a permanent rollout exception.

Installer tests reduce repeated setup and replace five individual historical fault cases with an existing upgrade-fault matrix while keeping a downgrade case. Some historical-source-by-fault combinations and independent diagnosis are reduced; the change is not lossless coverage equivalence. No fixed CI time or compute saving is promised.

The lightweight Linux tests execute the real receipt validator with simulated ioctl results for no flags, append-only, immutable and read failure. They do not set physical inode flags or replace kernel/filesystem integration tests. Existing chflags integration cases can still be skipped on Linux.

## Compatibility And Boundaries

The filesystem Desktop delivery group depends on the CLI handoff group so that its helper is present. Cross-version updates must include all managed groups; source, receipt, Core and profile checks remain in force.

Native capabilities remain the preferred route. The fallback does not restore missing create/fork/send callables or resolve Issue #251. It uses an invocation-local stdio process on the execution host; it adds no SSH transport, daemon, network listener, private-state reader or automatic installation. The existing exec/private-clone route remains separate.

Workspace-write requires explicit task authority and an exclusive writer. Child tasks retain the documented network, Apps/plugins/MCP, recursion and publication limits. Plugin skills do not autoload; callers supply verified instruction paths when needed. Feature flags are not proof of full host isolation. Writer conflicts stop without takeover, lock operations or automatic replay.

The recorded macOS CLI 0.166 and Linux CLI 0.167 evidence covers isolated read-only and Git-write fixtures plus remote Desktop placement. It does not qualify arbitrary versions or a production project. Cleanup does not prove that every descendant exited. The historical controller identity-drift cause remains unconfirmed.

Core v0.5.0 and its complete fixed snapshot remain unchanged. Prior release notes and all 19 existing installer catalog records must retain their original content. Repository source/package version comes from catalog.yaml; the annotated tag and provider Release metadata establish publication separately. Full ASD-STE100 conformance has not been verified. 繁體中文不宣稱符合 ASD-STE100。
