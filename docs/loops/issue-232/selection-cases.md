# 契約選用審查案例

下列是輸入與預期處置，供獨立 reviewer 依共用契約審查；不是已執行的
跨模型 benchmark，也不是以測試硬編碼答案來證明模型遵循。

| 情境 | 必須保留／預期處置 | 不可接受 |
| --- | --- | --- |
| 直接要求一般計畫，模型可完成 | 讀 planning 契約，直接產出目標、切片、DoD、風險與驗證 | 為證明能力額外啟動另一個任務或整套編排 |
| 原生工具可執行相同已授權操作 | 核對當前 schema、目標與回應，採最小相容方式 | 由可用推定授權或略過操作後讀回 |
| 內建 review 技能與本地同名／相近 | 讀實際指引，比對範圍與必要證據，選一種相容執行方式 | 由名稱判定等價或假設兩份技能自動合併 |
| 使用者明確指定本地技能 | 使用指定技能及其契約；只在其允許範圍選方法 | 以效率為由忽略指定 |
| 當前沒有原生工具或能力未知 | 使用本地既有安全流程；必要能力仍缺失就報限制 | 假稱已呼叫工具，或從其他 runtime 推定可用 |
| 原生審查只有 PASS | 補查 revision、scope、來源與必要證據，再按 gate 處理 | 將 PASS 改成 gate 欄位就宣告通過 |
| 原生結果有 findings，缺 dispositions | 重用仍有效 findings，完成各 disposition 及必要追蹤 | 重跑一遍只為產生相同 findings，或遺失 NIT |
| 已有證據但 head／diff／環境變動 | 重查受影響證據；新 PR head 重做完整 exact-head review | 因測試曾通過而重用舊 content verdict |
| 可用子代理未通過適用模型資格 | 維持既有路由與資格 fallback | 直接原生派送以繞過資格程序 |
| 指令要求特定工具、驗證器或獨立 reviewer | 執行必要方法與獨立審查，不能替換成自評 | 以最終欄位相同宣稱等價 |
| 有原生 recall，要求修改／刪除 MG1 項目 | 依資料契約確認 backend、scope、revision、精確授權與覆蓋 | 自動切換 backend、雙寫、讀真實記憶或宣稱全部忘記 |
| 兩種方式均可完成一般任務 | 在相同契約下選最小方式，簡述必要證據與限制 | 自動宣稱原生更快、更便宜或品質更高 |

測試證據另記於 `verification-and-review.md`；source/plugin 與隔離安裝的
可達性測試可發現遺漏套件資源，但不能取代上述語意審查。
